# 标签筛选牌组 · 插件配置

这些是「新建筛选牌组」窗口里的默认值，改完保存，重启 Anki 生效。
已经建好的牌组不受影响，要改请用「工具 → 标签筛选牌组…」里的「编辑」。

- **default_parent**：默认的「牌组位置」（父牌组路径）。
  - `标签筛选`：放在 `标签筛选` 这个父牌组下面（默认）。
  - 空字符串 `""`：直接建在顶层。
  - 也可以写成 `我的牌组::子牌组` 这样的多级路径。
- **default_states**：默认勾选的「取卡范围」状态，可选值：
  - `new` 未学习（`is:new`）
  - `learn` 学习中（`is:learn`，含答错后正在重学的卡）
  - `review` 复习中（`is:review -is:learn`，已毕业进入间隔复习的卡）
  - 默认 `["new", "learn", "review"]`（三个都勾）。三项互不重复，相加正好等于命中总数。
  - 注意：没有「已暂停/已搁置」选项。Anki 重建筛选牌组时一定会排除这两类卡，
    插件也不会去改动卡片的暂停状态，只会在预览里提示有多少张收不进来。
- **default_include_not_due**：默认是否「连还没到期的也收」，默认 `false`（＝只收到期）。
  - `false`：只收到期的卡（加还没学过的卡），学完的卡不会在下次重收时被拉回来。
  - `true`：连还没到期的卡也收——这类规则在管理窗口里叫「突击牌组」，
    **不会自动重收**（进牌组、启动 Anki 都不收），这样一轮才刷得完；
    想重新装满点「立即重新收卡」或「集中刷…」。
  - 「到期」按**卡片自己的到期时间**算：在筛选牌组里看卡片的原始到期日（`odue`），
    不叠加原牌组的每日新卡/复习上限；还没学过的新卡不受这个开关影响。
  - 老配置写法 `default_scope`（`due_new` / `all`）与 1.4.0 的反向字段
    `default_due_only`（`true`＝只收到期）都能自动识别并迁移成这个正向字段。
- **default_order**：默认的「收录顺序」，用 Anki 原生的顺序编号：
  - `0` 最早看过的优先，`1` 随机，`2` 间隔从短到长，`3` 间隔从长到短，
    `4` 遗忘次数最多，`5` 添加顺序，`6` 到期顺序（默认），`7` 最新添加优先，
    `8` 提取难度从难到易（需 FSRS），`9` 提取难度从易到难（需 FSRS），
    `10` 相对逾期优先。
- **default_limit**：默认的「单次收录上限」，默认 `9999`（1 到 99999）。
- **auto_rebuild**：管理窗口里「进入牌组时自动重新收卡（并在 Anki 启动时各收一次）」
  这个勾选框的值，默认 `true`。
  - `true`：进入筛选牌组总览时重收一次，Anki 启动后也对每个牌组各重收一次
    （只在规则和牌组实际设置一致、且确实还是筛选牌组时才重建）。
  - `false`：两种自动重收都不做；「立即重新收卡」按钮不受影响。
  - 无论这个开关是什么，「连还没到期的也收」的突击牌组都不自动重收。
  - 集中刷进行中的牌组一律跳过自动重收，不会把刷到一半的卡踢走。
- **update_check**：管理窗口里「启动时自动检查更新（每天最多一次）」这个勾选框的值，
  默认 `true`。打开时插件会从公开仓库
  `github.com/creeperboo/anki-tag-filtered-deck` 取 `version.txt` 比一下版本号，
  一天最多一次；检查结果和诊断信息写在插件目录的 `update.json` 里。

说明：集中刷是「点一下就用一轮」的临时动作，不写进规则、也不需要配置文件。
每次点击都会问「这次要不要影响原卡排期」，不记住上次的选择。它会**另建**一个
「`原牌组名`·集中刷」的临时牌组（原牌组的设置一个字都不动，只是暂时显示 0 张），
并弹一个「集中刷 · 牌组名」小窗：**关掉这个小窗就等于结束这一轮**——删掉临时牌组
（卡回原牌组）、按原规则重建原牌组。想接着突击就点小窗里的「再刷一轮」。
刷到一半切到别的牌组时会先问一句要不要结束。任何被托管的筛选牌组都可以用集中刷，
「不影响排期」的三档延迟按**卡片自己的原牌组**里设的新卡学习步骤换算
（多来源时取张数最多的那个，对话框会写明来源）。
运行日志写在插件目录的 `user_files\log.txt`，管理窗口底部的「打开日志文件」可打开。

「让 Anki 也自动检查插件更新」这个勾选框读写的是 Anki 自己的设置
（`mw.pm.check_for_addon_updates` / `set_check_for_addon_updates`），
不受这里影响，插件也不会主动去改它。

除了上面写明的两个 GitHub 地址，插件不做任何其他联网动作，也不会自动修改这些配置。
