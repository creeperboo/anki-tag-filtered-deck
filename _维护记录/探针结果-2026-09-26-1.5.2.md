## 本轮新增的三步在钉什么（就是用户这次的反馈）

1. `cram_ui_browser_end` —— 开一轮集中刷后，**先把界面放回临时牌组的总览页**，
   再真的切到**牌组列表**，让 Anki 自己发 `state_did_change`；探针把
   「要结束集中刷吗」的对话框替成"选结束"。
   > 探针自己踩过一个坑：直接从牌组列表 `moveToState("deckBrowser")` 是空操作，
   > 钩子根本不会发出来，会得到假阴性。所以这一步先回总览页再切牌组列表。
2. `cram_ui_browser_end_check` —— 收尾后逐条断言：
   - 插件确实问了「「…」还在集中刷。现在离开这个牌组，要结束集中刷…吗」；
   - 临时集中刷牌组被删掉（`temp_gone = true`）；
   - 原筛选牌组按规则收回来（7 张 == 规则口径）；
   - 集中刷会话清干净（`session = null`）；
   - 界面**还停在牌组列表**、选中的是**原筛选牌组**（`state=deckbrowser`、
     `selected=origin`）；
   - `_redraw_after_cram` 确实被调用了一次；
   - 插件日志里那一行是 **`结束集中刷后重画界面：…（现在 7 张，当前页面
     deckbrowser，画了 牌组列表）`**——1.5.1 这里会写成 `画了 无`，正是本次修的
     那处判定（`state == "deckBrowser"` vs 小写 `"deckbrowser"`）；
   - 重画那一刻原牌组张数已经是规则口径。
3. `op_return_values` —— 用替身包住 `aqt.operations.on_op_finished`，记录**每一个
   后台操作交给 Anki 的返回值**：本轮共 **24 次**，类型只有
   `OpChangesWithCount`（11）和 `OpChangesWithId`（13），**违规 0 条**
   （凡是 `list` / `tuple` / `int` / `None` 都会记一条违规）。
   这一步覆盖：启动重收、开始集中刷、再刷一轮、结束集中刷、保存规则五条路径。
   另外钉住两条兜底路：`_op_changes()` 一条原生结果都拿不到时返回的是
   `OpChanges`（不是 `None`）；「要删的临时牌组已经不在了」时
   `_remove_filtered_decks()` 也交出合规结果——1.5.1 这条路会返回 `None`，Anki
   读到 `.changes` 同样会弹「遇到了问题」，本轮一并修掉。

另外 `工具\run_anki_probe.py` 会把 Anki 自己的输出（`anki_stdout.log`）扫一遍，
出现 `on_op_finished` 或 `has no attribute 'changes'` 就判失败；本轮两者都没有。

## 复跑的老回归（同样 0 失败）

- 卡片总数不变、卡片回原牌组；
- 暂停卡 / 搁置卡的 `queue` 在整轮运行前后一模一样（`no_state_mutation`；
  这是本插件"绝不改卡片状态"承诺的守门步骤）；
- 自动重收开关关掉后：进牌组不重收、启动那一遍也不重收；
- 「连还没到期的也收」的突击牌组进牌组 / 启动都不自动重收；
- 集中刷期间原牌组与临时牌组的自动重收都被跳过；
- 集中刷的两条结束路径（关窗 / 小窗按钮）与「去刷题」落点；
- 「看收不进来的卡」集合与编辑器预览数字一致；
- 老规则（`scope` / `due_only`）迁移后生成的搜索式逐字不变。
