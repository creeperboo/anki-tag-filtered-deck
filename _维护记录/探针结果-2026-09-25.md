## 逐项结论

**统计口径（`a + b + c = N` 不变量）**

- 并集「唐诗 / 宋词」：`matched = 11`，
  `states = {new: 8, learn: 1, review: 2}`，8 + 1 + 2 = 11 = 命中总数。
  三个状态互不重复：`未学习 = is:new`、`学习中 = is:learn`、
  `复习中 = is:review -is:learn`。
- `collectible = 7`、`blocked = 4`（还没到期 1、暂停或搁置 2、已在别的筛选牌组 1）。
- 单标签人数：`唐诗` 5 张、`宋词` 8 张。

**「连还没到期的也收」开关**

| 规则 | 搜索式 | collectible |
| --- | --- | --- |
| `宋词` + 不勾未到期 | `(tag:"宋词") AND (is:due OR is:new)` | 5 |
| `宋词` + 勾未到期 | `tag:"宋词"` | 6 |

- 未到期的 I 在不勾时被排除（`i_due_kept = false`），勾上后收进来（`i_loose_kept = true`）。
- 暂停 / 搁置的卡不受这个开关影响，两边都收不进来（Anki 自身限制）。

**单选状态**

| 勾选 | collectible |
| --- | --- |
| 只勾「未学习」 | 3 |
| 只勾「学习中」 | 1 |
| 只勾「复习中」+ 不勾未到期 | 1 |
| 只勾「复习中」+ 勾未到期 | 2 |

**建组（并集）**

- 牌组名 `标签筛选::唐诗 + 宋词`，收录 7 张：A、B、C、D、E、H、J。
- 被排除的正好 4 张：F-暂停、G-搁置、I-复习未到期、K-已在别的筛选牌组。
- Anki 实际存下的设置：上限 9999、顺序 6（到期）、`reschedule = true`、搜索条件 1 条。
- 插件生成 `(tag:"唐诗" OR tag:"宋词") AND (is:due OR is:new)`，
  Anki 存成 `(tag:唐诗 OR tag:宋词) (is:due OR is:new)`；写法不同、含义一致
  （`col.find_cards()` 结果集相同）。插件写完立刻重建，所以读到的一直是 Anki 的规范写法。

**层级标签**

- 只选「唐诗」：收到 A、B、D、E 共 4 张，说明 `tag:唐诗` 自动包含子标签 `唐诗::格律`。

**交集**

- 「唐诗 ∩ 宋词」（含未到期）：牌组名 `标签筛选::唐诗 ∩ 宋词`，收到 D、E 共 2 张，
  与命中数一致；搜索式 `(tag:"唐诗" AND tag:"宋词")`。
- 空交集（`唐诗 ∩ 不存在的标签`）：预览显示
  「没有卡片同时带这些标签（交集为空），牌组建出来会是空的。」并列出每个标签单独的张数。

**作答共享复习记录（关键）**

在筛选牌组里答 A 这一张：

| 项目 | 作答前 | 作答后 |
| --- | --- | --- |
| 卡片 ID / 笔记 ID | 同一张，未变 | 同一张，未变 |
| 所属牌组 | 筛选牌组（`did` = 筛选牌组，`odid` = 源牌组） | 源牌组（`odid` = 0） |
| 类型 / 间隔 / 复习次数 | 新卡 0 / 0 天 / 0 | 复习卡 2 / 5 天 / 1 |
| 复习日志条数 | 5 | 6 |

- 全库卡片总数作答前后都是 11，一张没多也没少。
- Anki 原生行为：开着「按作答重排原卡」时，答完的卡当场送回源牌组，
  筛选牌组里只剩其余 7 张。

**自动重收**

- 从牌组列表进入该筛选牌组的空总览页：自动按规则收满 7 张（刚学完的 A 没回来）。
- 从学习界面返回总览（`review → overview`）：**不重收**，牌组保持为空。
- 把筛选牌组的上限从 9999 改成 5 后进入牌组：不重收（牌组保持空），
  规则被标记 `externally_modified = true`，Anki 里的上限仍是 5（没有被偷偷覆盖）。

**移动**

- 把牌组位置改成 `标签筛选::里层`：牌组改名为 `标签筛选::里层::唐诗 + 宋词`，
  旧名字不再存在、同名牌组只有 1 个（是改名不是新建），7 张卡照旧按规则收回来。

**删除（数据安全）**

- 对普通牌组调用删除：被拒绝并提示"这不是筛选牌组"，牌组还在。
- 确认框文案（成品包实测原文）：
  「要删除筛选牌组「标签筛选::里层::唐诗 + 宋词」吗？\n\n只删除这次筛选：
  里面的 7 张卡会立刻回到各自原来的牌组，\n卡片本身、复习记录和排期都不会丢。」
  ——**不再提恢复暂停/搁置**（本版不碰卡片状态）。
- 确认删除后：筛选牌组消失、规则被清掉；全库卡片总数仍是 11；
  所有卡片的所属牌组都回到源牌组，`odid` 全部为 0。

**失效规则清理 / 老规则迁移**

- 手工塞一条指向不存在牌组的规则，`cleanup_stale_rules()` 把它清掉了。
- 老 `scope=all` 的规则读入后变成 `states = ["new","learn","review"]`、
  `due_only = false`，搜索式 `tag:"诗"`（与老版本逐字一致）。

**搜索式规范化**

- 写入 `tag:"不存在的标签"` 后 Anki 存成 `tag:不存在的标签`；
  再重建两次写法都不再变化（所以插件判断"是否被外部改过"是比较稳定的字符串）。

**界面（端到端，真实建出窗口）**

- 牌组右键菜单：由插件管理 → `["编辑筛选规则…", "立即重建", "删除筛选（保留卡片）"]`；
  普通牌组 → 空；未托管的筛选牌组 → `["用标签规则接管这个筛选牌组…"]`。
- 浏览器左侧标签右键 → `["用它创建标签筛选牌组…"]`。
- 编辑器：状态框只有 `new` / `learn` / `review`（**没有** suspended / buried）；
  默认三个都勾、`due_only = true`、顺序 6、上限 9999。
- 「已有标签」面板：搜索「唐诗」筛出 `["唐诗", "唐诗::格律"]`；
  「加入所选」把「宋词」加进已选标签。
- 实时预览（只填「唐诗」，防抖 250ms 后）：
  「预计收录：3 张（上限 9999）／命中这些标签的卡共 5 张（未学习 4、学习中 0、复习中 1）；
  只有打勾的状态会被收进牌组。／另有 2 张这次收不进来：还没到期的 1 张、暂停或搁置的 1 张
  （暂停/搁置的卡 Anki 不会收进筛选牌组，插件也不会改动它们的暂停状态；
  想学它们请先在浏览器里取消暂停或取消搁置。）」
- 管理窗口：7 列，取卡范围列显示「未学习+学习中+复习中」，状态列「正常」。

**核心回归：暂停 / 搁置状态不被改动**

整个探针流程跑完（建组、重建、自动重收、删除）前后，F-暂停 / G-搁置 的完整快照一致：

| 卡 | 运行前 | 运行后 |
| --- | --- | --- |
| F-暂停 | `type 0, queue −1, due 6, ivl 0, reps 0` | 完全相同 |
| G-搁置 | `type 0, queue −3, due 7, ivl 0, reps 0` | 完全相同 |

`is:suspended` 集合运行前后都是 `[F]`，`is:buried` 集合都是 `[G]`。
（快照里 A 和 K 有变化，那是"在筛选牌组作答"和"另一个筛选牌组被清理"
造成的正常回流，与暂停/搁置无关。）

## 本轮修掉的真实缺陷

1. **规则里的「被外部改过」标记读不回来**：`normalize_rule()` 会丢掉
   `externally_modified`，导致写进配置又立刻在读的时候消失。已修（纯逻辑测试已覆盖）。
2. **写入后不重建会被误判成外部修改**：`add_or_update_filtered_deck` 之后立刻
   `rebuild_filtered_deck` 一次，让规则存的是 Anki 规范化之后的搜索式，
   否则第二次进入牌组会被判成"外部改过"，自动重收永久停摆。

## 两点说明

- 探针里 `anki_version` 字段是空的（探针取不到该属性），不影响结论；
  实际启动的是本机 Anki 26.9.3。
- 三状态口径下 `states` 的三项互不重复，因此 `a + b + c` 恒等于 `matched`；
  这是与"前一版五状态（会重叠计数）"的主要区别。
